## 2. Назначение — Intended Use

Модель решает задачу бинарной классификации фотографии гриба:

- `edible` (индекс 0) — съедобный по разметке датасета;
- `non_edible` (индекс 1) — несъедобный/потенциально опасный по проектной постановке.

Основное применение — учебная демонстрация компьютерного зрения, эксперименты с ML-пайплайном и прототип образовательного справочника. Пользователи — студенты, разработчики и исследователи проекта.

**Предсказание не подтверждает безопасность гриба и не должно использоваться для решения об употреблении в пищу.** Определение вида, токсичности, способов приготовления и медицинские рекомендации находятся вне области применения.

### Вход и выход

На вход API `POST /predict` поступает один файл изображения в multipart-поле `file`. PIL декодирует файл и переводит его в RGB. Затем применяются resize до 224 × 224, преобразование в тензор и нормализация: mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`. Вход сети имеет форму `[1, 3, 224, 224]`.

Сеть возвращает два логита. API применяет softmax и возвращает JSON с `predicted_class`, `confidence` выбранного класса, `probabilities` для обоих классов, `filename`, `latency_seconds` и метаданными модели в `model`. Класс выбирается через argmax; отдельного порога отказа от предсказания нет. Softmax-confidence не является проверенной вероятностью безопасности гриба: калибровка не оценивалась.

## 3. Факторы качества — Factors

На результат могут влиять освещение, фон, ракурс, масштаб гриба, резкость, перекрытия, цветопередача и видовая принадлежность. Качество для этих отдельных условий не измерено. Не подтверждена переносимость на новые регионы, камеры, виды грибов и фотографии вне распределения датасета.

Модель не проверяет, что на изображении действительно один гриб: отдельного детектора объектов и проверки входа на принадлежность предметной области нет. Семантика `non_edible` ограничена данными: исходный класс `poisonous` переименован в `non_edible`, что само по себе не обеспечивает покрытие всех несъедобных грибов.

## 4. Метрики — Metrics

Положительный класс — `non_edible`.

| Метрика | Что измеряет |
| --- | --- |
| Accuracy | Доля правильных ответов по двум классам |
| Precision `non_edible` | Доля действительно опасных по разметке среди предсказаний `non_edible` |
| Recall `non_edible` | Доля найденных примеров `non_edible` среди всех примеров этого класса |
| F1 `non_edible` | Гармоническое среднее precision и recall; критерий выбора checkpoint |
| ROC-AUC | Качество ранжирования по вероятности `non_edible` при изменении порога |
| Loss | Взвешенная cross-entropy на соответствующей выборке |

Критическая ошибка — истинный `non_edible`, предсказанный как `edible`; поэтому recall особенно важен для интерпретации риска. Оптимизация F1 не задаёт допустимый уровень такого риска. Для двух классов argmax соответствует выбору `non_edible` при вероятности выше 0.5; при равенстве выбирается первый класс (`edible`). Доверительные интервалы, калибровка и разброс результатов по нескольким seed не представлены.

## 5. Данные оценки — Evaluation Data

Источник — Kaggle [Edible & Poisonous Mushroom Classification](https://www.kaggle.com/datasets/benedictusjason/edible-and-poisonous-mushroom-classification). Сохранено исходное разбиение на train/validation/test. Validation используется для scheduler, early stopping и выбора лучшего checkpoint; test — для итоговой оценки выбранного checkpoint. Внешней независимой оценки нет.

| Выборка | `edible` | `non_edible` | Всего |
| --- | ---: | ---: | ---: |
| Validation | 150 | 132 | 282 |
| Test | 150 | 132 | 282 |

Подготовка данных проверяет читаемость, преобразует изображения в RGB и сохраняет JPEG 224 × 224 с сохранением пропорций через padding. На validation/test далее используются resize, тензор и нормализация без случайных аугментаций.


## 6. Обучающие данные — Training Data

Тот же Kaggle-датасет: train содержит 2256 изображений, из них 1200 `edible` и 1056 `non_edible`. Всего в трёх выборках 2820 валидных изображений: 1500 и 1320 соответственно; по EDA битых файлов нет, обнаружено 1296 групп точных дубликатов.

Разметка берётся из каталогов исходного датасета, `poisonous` преобразуется в `non_edible`. Независимая экспертная проверка всех меток не задокументирована. Файлы данных исключены из Git.

После общей подготовки на обучении применяются RandomHorizontalFlip (p=0.5), RandomRotation (±12°), ColorJitter (brightness 0.15, contrast 0.15, saturation 0.12), преобразование в тензор и та же нормализация. Описание ETL: [prepare_dataset.py](src/data/prepare_dataset.py).

## 8. Этические аспекты — Ethical Considerations

Основной риск — вред от ложного ощущения безопасности после ответа `edible` или высокого confidence. Оба ответа должны интерпретироваться только как учебная классификация. Необходимо явно сообщать об ограничениях пользователю демонстрационного приложения.

Репрезентативность данных и корректность меток не подтверждены экспертной валидацией. Текущая модель не даёт оснований распространять результаты на все виды грибов. При сборе новых фотографий следует учитывать права на изображения и возможность наличия в кадре людей или иной личной информации; отдельная оценка приватности в проекте не представлена.

## 9. Ограничения и рекомендации — Caveats and Recommendations

- До повторной оценки удалить межвыборочные дубликаты и сформировать разбиение по группам связанных изображений; проверить также близкие дубликаты.
- Собрать независимый внешний test с экспертной разметкой и оценить recall по видам и условиям съёмки.
- Измерить калибровку, неопределённость и качество на посторонних изображениях; исследовать отказ от ответа и пороги с учётом цены ошибок.
- Учесть различие preprocessing: ETL использует padding, а API для произвольной загруженной фотографии выполняет прямой resize. Качество на таких загрузках отдельно не измерено.
- Версионировать веса вместе с данными, конфигурацией и отчётами. Сохранённые метрики описывают указанный baseline, а не любой checkpoint, подключённый через `MODEL_PATH`.
- `GET /monitoring` показывает сохранённые test-метрики и эксплуатационные показатели (запросы, ошибки, latency, ресурсы). Без истинных меток новых запросов он не измеряет текущее качество предсказаний и не выявляет деградацию автоматически.
